Overview

A real-time multiplayer quiz game modeled on Kahoot, built on a client–server architecture over TCP sockets. A multithreaded C server hosts up to four game rooms of four players each (16 concurrent players), runs the rounds, and scores the answers; a C++ client with an SFML graphical interface lets players join a room, answer timed questions, and follow live results. Players can also upload their own question banks to the server.

Key Features

Multiplayer Rooms

A game starts once four players join a room; the server runs up to four rooms in parallel with one thread per room.

Timed Rounds

Each question has a countdown; unanswered questions score zero, and the highest total score wins.

Live Results

After every question, players see the answer distribution, their own result, and the current scoreboard.

Custom Question Banks

Players upload .txt question files, which the server validates and adds to its question pool.

Architecture

Server (C)

  • Spawns a pthread per game room
  • Uses select to receive answers from all players concurrently
  • Locks a room with a mutex while a game is running so no one joins mid-game
  • Handles disconnects and resets the room when a game ends

Challenges & Solutions

Keeping the GUI in sync with the server
Rendering and listening with select run in the same loop, so the UI sometimes drew before a message arrived. We introduced fixed notification strings that the client can recognize immediately to switch screens.
Missed messages when the server sends too fast
Added short 100–200 ms gaps between notifications and other messages so the client has time to read each one.
Byte-order mismatch between Linux and macOS
Used htobe64 / be64toh with conditional compilation so file sizes are transferred consistently on both platforms.
